AI LotteryReroll
OVERVIEW

Spot a bad draw in two minutes. Swap it out without losing work.

Open a new AI session and sometimes it's sharp, sometimes it's dull — and it gets duller the longer you go. That's not your imagination: official postmortems and research papers confirm it. Reroll does three things:

1 · Test

Test the opening

/canary asks 4 small questions; score the answers here. Bad draw? Start over.

2 · Clean

Clean start

On a good draw, /rewind to before the test. The test vanishes from the context; then start real work.

3 · Swap

Lossless swap

When it goes dumb for good, /handoff writes a handoff doc and a new session takes over with /pickup.

The key idea: your work lives in files and git, not in the session. So a session can be thrown away any time and replaced with a fresh draw.
概览

开局 2 分钟识别坏卡，变傻时无损换卡

新开一个 AI 会话，有时聪明、有时傻，而且越往后越傻。这不是错觉：官方事故复盘和论文都证实了。Reroll 做三件事：

1 · 测

开局测卡

/canary 发 4 道小题，用本软件的打分器打分。坏卡直接重开。

2 · 净

干净开局

好卡用 /rewind 退回测试之前，测试内容从上下文里彻底消失，再开始正事。

3 · 换

无损换卡

变傻救不回来时，/handoff 写交接文档，新会话用 /pickup 接手。

核心认知：工作成果在文件和 git 里，不在会话里。所以会话可以随时丢掉，换一张新卡。
PROBLEM & EVIDENCE

Why you get bad draws

Session quality comes from three layers stacked on top of each other.

Layer 1Opening

The server lottery

Which server your request lands on, how busy it is, what the default reasoning effort is. Routing is sticky: land on a bad server at the start and the whole session stays there.

↓ stacks with
Layer 2First ~10 turns

Path lock-in

In the first few turns the model forms a reading of what you want, and every later turn builds on it; it rarely goes back. Read you right and it "gets you"; read you wrong and it never does.

↓ stacks with
Layer 3Later on

Self-pollution

The context piles up with its own mistakes, rejected approaches, and back-and-forth. The model keeps imitating "itself in this conversation" and keeps erring. Longer gets blurrier, and compaction drops details.

问题与证据

为什么会抽到坏卡

会话的质量由三层原因叠加决定。

第 1 层开局

服务器抽卡

请求被分到哪台服务器、服务器忙不忙、默认推理强度是多少。路由是黏性的：开局分到坏的服务器，整个会话一直落在那里。

↓ 叠加
第 2 层前 10 轮

路径锁定

模型在头几轮对“你想要什么”形成一个解读，之后每轮都建立在它上面，很少回头。解读对了就“懂你、替你想”，偏了就一直“不懂你”。

↓ 叠加
第 3 层越往后

自我污染

上下文里堆积了它自己的错误、被否定的方案、来回拉扯。模型会照着“这个对话里的自己”继续犯错。越长越糊，压缩时还丢细节。

CLEAN START

Good draw — now keep the test out of the conversation

The idea: roll the conversation back to before the test. The test questions, answers, and skill text all leave the context, but the session itself — the good draw — stays.

Claude Code

1

The first message of the new session is /canary

Send nothing before it, so rolling back lands on a completely blank start.

2

Scored it: good draw

Use it right away. Leave it idle too long and the server layer may change.

3

Type /rewind (or press Esc twice)

Pick the /canary message in the list — that means "go back to before it was sent".

4

Choose "Restore conversation only"

No need to restore code: the test didn't touch any files.

5

The input box refills with /canary — clear it and type your real task

To confirm it's clean, run /context and check usage is back to a fresh start. Don't ask the AI "what were we just talking about?" — that question itself enters the context.

ChatGPT / web chats

1

Before starting: pick a model by hand, turn memory off

Not Auto, which can switch models every turn. Under Settings → Personalization, turn off "Reference saved memories / Reference chat history", or the test may be remembered and leak into future chats.

2

Good draw: edit the first message

Use the edit button on the first message, replace the test with your real task, and send. Editing a message is the web chat's /rewind: everything after it moves to another branch and leaves the context. Don't send a new message — the test would stay in the context. (Codex CLI: press Esc twice, like Claude Code.)

Note: after rolling back there is no trace of the test in the context — that part is certain. Whether a good draw stays good depends on the server layer, which can't be guaranteed. Keep an eye out for the signs under "When it goes dumb".
干净开局

测完是好卡，怎么不让测试污染后面的对话

原理：把对话退回到测试之前。测试的问答和 skill 内容都从上下文里删掉，但会话本身保留，也就保留了这张“好卡”。

Claude Code

1

新会话的第一条消息就是 /canary

测试前什么都不发，这样退回去就是一个完全空白的开局。

2

打完分，是好卡

马上开始用，不要放着。闲置太久，服务器那一层可能变化。

3

输入 /rewind（或连按两下 Esc）

在列表里选中 /canary 这条消息，表示回到它发出之前。

4

选「只恢复对话」

不需要恢复代码，因为测试没有改过任何文件。

5

输入框里会回填 /canary，清空它，写你的正事

想确认干净了：输入 /context，看上下文用量回到了开局水平。不要问 AI “我们刚才聊了什么”，这句话本身就会进上下文。

ChatGPT / 网页版

1

开局前：手动选定模型，关掉记忆

不要用 Auto，否则每轮都可能换模型。设置 → 个性化里关掉“参考记忆 / 参考聊天记录”，否则测试内容可能被记下来，影响以后的对话。

2

测完是好卡：编辑第一条消息

点第一条消息的编辑按钮，把测试题换成正事，再发送。网页版的「编辑消息」就是它的 /rewind：这条之后的内容挪到另一个分支，不再算进上下文。不要新发一条，新发一条测试内容还在上下文里。（Codex 命令行版和 Claude Code 一样，连按两下 Esc。）

说明：退回之后上下文里没有任何测试的痕迹，这一点是确定的。“好卡”会不会一直好，取决于服务器那一层，没法百分之百保证。所以中途仍然要留意「变傻急救」里的信号。

    安全说明
    
会不会卡死电脑、占满硬盘、弄坏文件

    
不会。每一项会读写什么，列在下面。

    

      
部分会做什么防护

      
        
/canaryAI 只用文字回答。第 4 题会读文件第一行就是硬性规则：不运行任何命令，不创建、修改、删除任何文件。200GB CSV 题只写代码、不执行，不会生成测试文件

        
/handoff运行只读的 git 命令；写一个 HANDOFF.md这是唯一会写的文件。如果项目里已有同名文件且不是交接格式，会停下来问你，不会覆盖。不会自己 commit

        
/pickup读 HANDOFF.md，运行只读的 git 命令确认前不改任何东西，等你点头才动手

        
本软件：接力打开页面时读取 ~/.claude/projects 和 ~/.codex/sessions 里的会话记录；只新建一个文件夹 <项目>/.relay/<时间>/只读。写出之前先把密码和密钥打码。.relay 文件夹自带 git 忽略规则。从不覆盖；不运行任何程序（连 git 都不运行）；数据不出本机

        
本软件：安装写入 ~/.claude/skills/ 下的四个 skill 文件夹先显示计划再执行。已有同名 skill 会先挪到 ~/.claude/skills-backup/时间/，不删除任何东西；内容相同的跳过

        
本软件：导出在你选的文件夹里新建一个子文件夹总是新建（重名就加 -2、-3），不覆盖任何已有文件

        
本软件：运行一个窗口不联网（只有你点外部链接时用浏览器打开），不申请权限，没有后台进程，关窗即退出。经过 Apple 公证

        
通用版提示词在 ChatGPT 里只用文字回答提示词要求不运行代码；就算运行，也是在对方的云端沙盒里，碰不到你的电脑
